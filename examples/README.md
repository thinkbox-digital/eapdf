# EA-PDF examples

The 24 primary examples were regenerated on 2026-11-07 with
`EmailToPDFA 1.6.0-beta.19`. They pass the standalone Java validator, including
PDF/A, EA-PDF and selected ISO checks. Collection children are checked as part
of validation. Accessibility and embedded search indexes are enabled; optional
PREMIS and finding-aid outputs are disabled.

Filenames use the input type, input filename stem and profile. Multiple-input
examples add `_archive` after the first input name; their manifests list every
input. For example, `mbox_enron-sample_1m.pdf` comes from `enron-sample.mbox`.
Normal conversions also retain the input stem; `auriza.mbox` produces
`auriza_1m.pdf` in archive mode or `auriza__subject_000001.pdf` per message.

Two additional beta.19 examples make the public set **26 PDFs**:

- [Enron archive](mbox/mbox_enron_1m.pdf): 1,433 messages from `in/enron.mbox`.
  Conversion and source-preservation comparison completed, and its full-text
  index covers all 1,839 pages. Standalone validation is **INCOMPLETE**: bundled
  veraPDF raises the same runtime exception seen in beta.18, so PDF/A and the
  dependent ISO assessment are unavailable. It has no reported EA-PDF FAIL
  rules, but it is not a conformance-passing example.
- [Missing-Date example](eml/eml_missing_date_1s.pdf): deliberately removes only
  the top-level Date header from the Agenda source. PDF/A and selected ISO
  checks pass; EA-PDF validation **fails as expected** with `MESSAGE_SENT_XMP`.
  This demonstrates incomplete source metadata without inventing a sent date.

Sources:

- EML: `in/Agenda and timeline slides.eml`, `in/eml_01_403.eml`.
- MSG: `in/TxtSampleEmailWithAttachment.msg`, `in/test.MSG`.
- PST: `in/quality-attached-message.pst`.
- MBOX: `in/enron-sample.mbox`, plus `in/enron.mbox` for the additional archive.

PST and MBOX single-message examples are unchanged copies of one message child
from the corresponding collection. Their manifests identify that child.
Non-isolated profiles preserve exported messages rather than the original
PST/MBOX containers; isolated profiles omit those sources.
The small PST has seven messages; large PSTs were excluded.

Each format’s `manifest.json` records hashes, inputs, creator/validator builds,
configuration, processing limits and validation results. Original input hashes
were checked before and after regeneration. The demonstration creator identity
is Thinkbox.DIGITAL for the primary matrix and negative example, and
EmailToPDFA 1.6.0-beta.19 for the additional Enron archive. Neither identifies
the original email author.

Conversion logs and standalone Java reports are retained in local verification
records. These automated checks do not constitute independent certification.
Historical Arlington results describe earlier generated bytes; that separate
object-model audit was not rerun for this regeneration. See
[checker scope and corrections](../docs/ARLINGTON_VALIDATION.md).

Regenerate the 24 primary examples using `scripts/regenerate_email_samples.py`;
see the project README for configuration and build options. Temporary staging uses `/tmp` and is
removed after success or failure. Only a fully validated primary set replaces
those 24 samples.
