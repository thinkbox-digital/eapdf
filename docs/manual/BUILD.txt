Build the user manual from docs/manual/user-manual.html with Java 21 and
requirements-docs.txt installed:

python3 scripts/manual/build_manual.py \
  --creator-jar /path/to/emailtopdfa-version.jar \
  --validator-jar /path/to/eapdf-validator-version.jar

The script builds ordinary PDF/A-2b, runs the bundled veraPDF engine and records
source hashes, JAR hashes and the edition in docs/manual/build-receipt.json.
Intermediate files stay in /tmp and are removed. The PDF manual is separate from
the website; rebuild both after changing the guide.

Screenshots use fictional mail and are captured from the current released
applications. To refresh them, build the actual applications and reader, prepare
the temporary fixtures with scripts/manual/prepare_capture.py, then use
CaptureScreenshots.java and capture-browser.mjs. CaptureScreenshots accepts
optional width and height arguments for genuine native-size homepage captures;
the Creator currently requires at least 1200×955. Set MANUAL_SCREENSHOTS and
MANUAL_VIEWPORT to make a separate browser capture. Inspect the rendered manual,
contents and bookmarks after rebuilding. Keep source files, font/license notices
and the verification receipt. Remove only task-owned files.
