CIDSet policy correction (2026-10-27)
The forced CIDSet removal and mandatory absence check described in this historical
report have been reverted. The forthcoming ISO 19005-4 revision changes "shall"
to "should": https://github.com/veraPDF/veraPDF-library/issues/1647#issuecomment-6457552448
PDFBox now uses its normal save-time subsetting. The recorded PDFs and receipts
remain unchanged; CIDSet absence is no longer an extra acceptance requirement.

Confirmed issues and corrections

1. Seven EML messages declared the unsupported character set windows-3839 and
crashed the creator. Display recovery now uses strictly valid UTF-8, otherwise
Windows-1252, with a warning. The original email bytes are retained. The guessed
display encoding is not represented as a verified sender encoding.

2. Several mailing-list exports have a complete date and time but no timezone.
The creator previously rejected them. It now preserves strictly parsed ctime
values as timezone-free XMP dates and retains the original Date as Raw-Sent.
It does not invent UTC or borrow a Received timestamp. Missing dates still fail.

3. A real HTML table produced a Div directly inside a table row. The correction
preserves existing cells while removing the anonymous wrapper, or supplies a
cell around actual non-cell content. The original failing sample1.mbox now
passes Java validation.

4. Other real HTML contains paragraphs inside styled inline wrappers. Those
wrappers and enclosing paragraphs are normalized into block groups without
changing the visible content. A regression uses the original Acceleo email.

5. A real PST has a valid empty RTF body. Empty HTML rendering was incorrectly
treated as a conversion failure. The creator independently checks the RTF text,
retains the original RTF, and reports the recovery. Unrendered RTF images and
objects are not silently accepted as empty content.

6. The PST library miscalculated row offsets after the first ANSI data block.
This broke recipient lists and sometimes folder iteration. The local correction
uses the proper ANSI/Unicode payload size and computes each row offset directly.
All six originally failing recipient tables now pass, including lists of
139–270 recipients. The copied library source retains its original notices.

7. The PST library treated subnode index blocks as leaf data blocks. A narrow
adapter now follows their leaf references. All 23,173 messages and 65,783
recipient rows in pst_22_200401-06JanJun.pst were inspected successfully afterward.

8. Missing PST attachment payloads caused an unexplained null-pointer crash.
The creator now reports the input, message descriptor, and attachment position.
It still refuses to invent an empty attachment or silently discard it.

9. Java validation used recursive traversal of a PDF object graph as though it
were a shallow tree. It now uses an iterative, cycle-safe traversal with a
bounded container count. Ownership-check work scales with page count and has a
hard upper cap. Files beyond the supported inspection budget remain incomplete.

10. The native CPU ceiling counted all worker threads against a one-thread time
allowance. It now accounts for worker processor capacity while the supervisor
continues to enforce the same elapsed-time limit. The corpus runner bounds both
case concurrency and worker concurrency, and gives Java validation enough heap
for the larger archives.

11. Large PST validation repeatedly recomputed attachment ownership for every
message and every native file. Runtime stack samples confirmed this bottleneck.
The validator now caches each immutable attachment-owner result and indexes
email identities once per validation. All duplicate identity matches are kept.
The changes do not turn ambiguous ownership into a unique match.

12. PST attachments with Content-ID were excluded from the PDF attachment count,
although the retained MIME source still contained named attachments. This even
affected Word documents. They now count as attachments and retain the same
native payload bytes, consistent with EML handling and both validators.

13. A native Word attachment retained the obsolete MIME label multipart/appledouble.
Exporting its binary bytes as a base64 multipart produced a checksum mismatch.
The payload is now exported as application/octet-stream, with the old label
retained in its description and a warning. The bytes are unchanged.

14. Structure validation repeatedly scanned the entire logical tree to find
each element's immediate children and each field value's siblings. Runtime
samples confirmed the cost on archives with hundreds of thousands of objects.
The validator now indexes children once, preserving parent identity and order.

15. Antivirus text notices in the May and April PSTs have Content-ID values.
Exporting those native attachments as inline text made them look like additional
message bodies. They now have an explicit attachment disposition; their content
IDs and original payload bytes are retained. Real regression messages include
mailsecurity.txt and alert.txt.

16. Jakarta Mail can ignore a declared transfer encoding for message subtypes
such as message/delivery-status. The reader and Java validator now decode the
raw part according to that header. The May PST's ATT11471.txt contains 201 original
bytes; counting its base64 representation caused a false size/checksum failure.
The independent Python MIME handling already reads the decoded payload.

17. PDFBox generates CIDSet during font subsetting inside save(). Current
collection examples contained the deprecated entry, including embedded message
PDFs. The creator now finishes the same pending subsetting queue first, clears
it, and removes CIDSet from font descriptors only when XMP identifies PDF/A-4.
This covers PDF/A-4, -4e and -4f, including collection children and finding aids.
PDF/A-3 uses the original font path. Embedded font programs, CIDToGIDMap and
ToUnicode remain intact. The tests compare program and mapping bytes, rendered
pixels and extracted multilingual text. veraPDF passes the PDF/A-3U and PDF/A-4
controls. Independent qpdf/pikepdf checks reject the old examples and accept
the corrected font control; Poppler rendering and extracted text are identical.
The independent check is limited to CIDSet, not a second full PDF/A certification.
PDFBox source: https://github.com/apache/pdfbox/blob/3.0.8/pdfbox/src/main/java/org/apache/pdfbox/pdmodel/font/PDCIDFontType2Embedder.java

The regenerated examples now pass all 188 independent CIDSet inspections:
24 primary PDFs, eight finding aids and 156 embedded message PDFs. These checks
covered 1,086 font descriptors. The complete example matrix also passed Java
validation. A real two-page email retained byte-identical Poppler rendering and
text after CIDSet cleanup, along with all 12 font-program/glyph-map entries.

Other observed input quirks

Several Outlook files disagree internally: a dedicated Message-ID property
differs from the retained transport header, or the declared preferred body is
missing while another body is available. Existing recovery warnings are kept.
These differences must not be hidden by changing the original source bytes.
The corpus also contains detached email signatures. Retention of a signature
does not verify it; the creator explicitly reports that it was not verified.
Counts of log warnings are not counts of affected messages, because supervised
conversion can repeat warnings in its final summary.

Limits that must stay visible

Valid Outlook messages without inspectable original headers, or with unsupported
native attachment evidence, can still receive an incomplete validation result.
That is not a passing result and is not proof of a specification violation.

The genuine PST folder inventories total 274,543 items. An attempted conversion
of a PST is not proof that every message in it was converted. Complete exports
may stop at a missing payload, a source defect, or the existing whole-job count,
metadata, temporary-storage, output-size, or time limits. No sampled mailbox is
being represented as a complete export. Final per-file outcomes appear below.

A separate scan of all seven ANSI PSTs enumerated 269,247 items and 580,109
recipient rows with no errors after the parser repairs. This scan checks folder
and recipient reading; it is not conversion or attachment-payload verification.
May–July 2005 enumerates 48,129 physical items versus 48,131 advertised folder
items. The entire difference is a search folder advertising two results but
returning no children. Search results can refer to existing messages; this is
not evidence that two additional physical emails should be invented.
