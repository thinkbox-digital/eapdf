Top-level rule migration: 213 to 229 rules
All current rules are numbered in specification page order. Page-less operational diagnostics are last.
The old numbers describe the retained 213-rule checkpoint; codes identify the current predicate.

Old #1 SOURCE_IN_ISOLATED:
  #1 SOURCE_IN_ISOLATED [printed p7 / PDF p14 / PROFILE-ISOLATION]: Isolated status describes absent, modified or untrustworthy original email-source linkage. Do not turn this into a blanket prohibition on every Source associated file: object-level Source assets are allowed. Catalog original-email provenance and partial-source cases require their own reviewed applicability.

Old #2 EAPDF_CONFORMANCE_VALUE:
  #2 EAPDF_CONFORMANCE_VALUE [printed p7 / PDF p14 / T1-c]: For all profiles: pdfmailid:conformance is lowercase text with value s si m mi c ci; i is last if present. The normal-string value is exact; URI/array values and surrounding whitespace cannot supply a listed Text value. Qualified simple strings remain permitted.

Old #3 PDFA_PART:
  #3 PDFA_PART [printed p8 / PDF p15 / T2-c]: Prerequisite: the finished PDF must pass veraPDF validation for an EA-PDF-permitted PDF/A level: PDF/A-3a, PDF/A-3u, PDF/A-4, PDF/A-4f or PDF/A-4e. This check identifies the declared PDF/A part; it does not repeat PDF/A validation. A declaration alone is not a passing result. Extra EA-PDF restrictions and applicable ISO/TS 32005 checks remain separate.

Old #4 PDFA_CONFORMANCE:
  #4 PDFA_CONFORMANCE [printed p8 / PDF p15 / T2-c]: After successful veraPDF validation of the finished PDF, verify that its declared PDF/A conformance level is one permitted by EA-PDF: 3a, 3u, 4, 4f or 4e. This is an allowed-level check, not independent proof of PDF/A conformance. The descriptive Table 2 profile matrix differs from section 9.1; the project follows the normative section 9.1 list.
