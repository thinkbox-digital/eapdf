# Browser compatibility and installation scope

The current builds share the same TypeScript viewer and patched PDF.js, with
browser-specific background/manifest configuration generated by the build.
[Project status](../../docs/PROJECT_STATUS.md) records the released versus local
source baseline; [installation](beta-release.md) gives the tested beta workflow.

| Item | Chromium | Firefox |
| --- | --- | --- |
| Declared minimum in build script | 156 | 158.0 |
| Manifest | V3 | V3 |
| Background | Module service worker | Module event-page script |
| Installation exercised | Unpacked development extension | Temporary development add-on |
| Release browser gates | Full Chromium acceptance, inspection oracle, archive-memory and signed-index checks | Temporary installation/UI acceptance, file drops and signed-index checks |
| Store signing/review | Not completed | Not completed |
| Wider platform promise | Other browser/OS combinations require explicit acceptance | Other browser/OS combinations require explicit acceptance |

A declared minimum is not evidence that every OS/browser version above it was
tested. Exact CI tool/browser versions and results belong to their recorded runs.
The initial M0 checkpoint used Chromium 156.0.8078.47 and Firefox 158.0.1;
those historical versions are not a claim about every later release environment.

Both packages bundle executable JavaScript, workers, codecs and fonts. CSP permits
packaged code and explicitly requested linked-PDF fetches, not remote scripts or
JavaScript string evaluation. Firefox uses background.scripts and the retained
Gecko development identity; Chromium uses a background service worker. Picker/drop
bytes do not require a file:// permission. See [security boundaries](security.md)
for current worker, extraction, fetch and retention policies.

Before commercial distribution, choose ownership of extension identities/update
channels, complete signing/store/privacy review, and exercise headed toolbar,
context-menu and site-permission interactions on the named supported platforms.
Temporary extension-page tests alone do not establish those behaviours. Browser
shutdown/sandbox diagnostics must be distinguished from application failures in
the actual test results.

Historical API parity reports remain in this directory as dated evidence. Use
[the test matrix](test-matrix.md) and [PDF.js patch maintenance](pdfjs-patch-maintenance.md)
for current reproduction and upgrade boundaries.
