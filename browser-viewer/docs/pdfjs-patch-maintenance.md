# Reproducing the PDF.js patch stack

Upstream PDF.js is pinned to **6.5.438**, commit
`0a4153349dc473ba950fc17941c5ca7eda43c1de`. The npm installation remains
unmodified and supplies the original rendering assets/notices. The new public
method is built from upstream source, not injected into compiled JavaScript.

`vendor/pdfjs-patches/0001-document-parts.patch` changes three existing files:
`src/core/catalog.js`, `src/core/worker.js`, `src/display/api.js`; it adds
`src/core/document_parts.js`. The patch has no EA-PDF application dependency.
`manifest.json` records the exact archive hash, relevant pristine source hashes,
upstream lockfile hash, local build/test input hashes and both generated outputs.
`vendor/pdfjs-patched/` contains the generated display/worker bundles.

Normal `npm run build` verifies the source/build-input/output hashes and copies
those generated bundles. It does not need GitHub, Python, Java, a backend, or the
upstream 931-package development toolchain. The extension is entirely local.

## Clean source reproduction

Use Node 24.19.0 and npm 11.17.0, with Git, curl and tar available:

```sh
npm run verify:pdfjs
npm run build:pdfjs
```

The second command downloads the exact upstream archive (about 100 MiB), verifies
its SHA-256, extracts into a new `/tmp` directory, checks pristine source hashes,
and runs `git apply --check` followed by `git apply`. It installs upstream's exact
package-lock with `npm ci --ignore-scripts`, skipping browser downloads, then
builds only display/worker bundles with upstream's own bundle functions. Source
tree and build products are removed afterward, including on failure. npm may
use its ordinary download cache. First reproduction needs registry/GitHub access.

With a previously downloaded archive:

```sh
npm run build:pdfjs -- --archive /absolute/path/pdfjs-source.tar.gz
```

The same SHA-256 check is mandatory. Source archive SHA-256:
`eead5ce4cdc7682a791cb5661de089f1f89b6679593f11d6240e20186ac051ae`.
An actual clean detached Git checkout of the pinned commit was also tested with
`git apply --check`; the patch does not depend on archive-specific file changes.

`build-task.mjs` appends a development task to the temporary upstream gulpfile;
it is not part of the runtime/core patch. Build version/commit are supplied from
the pin, without requiring full Git history to calculate a release number.
Upstream normally randomizes its INTERNAL_EVT build define. The task explicitly
uses the original 6.5.438 npm value, `0a475cb6-573c-46ed-869d-fa7c5839d995`, so clean
builds remain identical without rewriting output JavaScript. This is an existing
build constant, not a generated runtime credential.

Each reproduction runs the focused patch tests against the actual patched core and
133 upstream specs covering catalog, primitives, message handlers, streams, parsing,
evaluation and XML. Of these, 132 pass and one requires OffscreenCanvas unavailable
in Node (recorded pending). Patch 0002 also sets ordinary DecodeStream allocation
ceilings: 64 MiB for ordinary buffers and a 256 MiB worker allocation allowance.
The large-archive patches size cross-reference decoding from its validated layout,
reclaim private structural decoder buffers after parsing, and store cross-reference
records in sparse typed-array pages. Parsed-object caching retains 100,000
entries with constant-time circular-queue eviction; evicted objects remain retrievable, and weak references preserve the
identity of objects still used by page and structure readers. Complete archive
walks yield periodically and release processed queue records. These cache
policies do not limit the number of objects inspected.
Catalog metadata inspection permits up to
128 MiB with a scoped decoder allowance; ordinary 64 MiB buffer limits are restored
after metadata extraction, and exhaustion remains explicit. Document-part and annotation mapping each
use one page-tree scan instead of repeated page lookup. The source
tests load upstream's pinned core-js Map support because Node 24 lacks
Map.getOrInsertComputed, which is otherwise handled by upstream's legacy build.
No polyfill is added to the browser package by this test setup. The full upstream
rendering/integration test suite is not run by this narrow source command.

The default command compares regenerated bytes with the stored bundle hashes and
fails on any mismatch. It never silently updates expectations or artifacts.

## Intentional patch updates

1. Start from a fresh source tree at the pinned revision; edit only the scoped
   core/display/worker changes and export a reviewed source patch.
2. Review the patch, core tests and public TypeScript contract together. Update
   corresponding `localInputs` hashes in the patch manifest. A dependency/source
   pin change requires its own review; do not relax hash checks.
3. Run `npm run build:pdfjs -- --archive /path/to/archive --write` to deliberately
   replace generated bundles and output hashes. Review all changes.
4. Run the same command **without** `--write` from another clean temporary build;
   both output hashes must match. Then run `npm run check`, `npm test` with the
   installed Chromium path, and `npm run test:m1` in its pinned reference environment.
5. Reload the unpacked extension and reopen the viewer tab. Bundled code already
   loaded in a tab/worker does not automatically change when disk files change.

The second patch, `0002-document-assets.patch`, adds generic associated-file,
metadata and collection inspection and an opt-in DecodeStream allocation ceiling.
All patches listed in the manifest are applied and hash-checked by the reproduction command. M6 rebuilt
the current stack byte-for-byte and reran all 13 focused and 73 selected upstream
tests. The extension SBOM records the exact patch-manifest hash; build-info.json
records every shipped file hash. The full upstream rendering suite is not part
of that command.

The 0.5 viewer also packages the unmodified, hash-pinned upstream web component
bundle solely for StructTreeLayerBuilder. It does not instantiate PDFViewer,
PDFScriptingManager, or an annotation-action layer. The interpreter remains
excluded. Returned structure trees are bounded before recursive DOM construction.

Indirect attachment extraction refetches a private stream decoder for each request.
After producing detached bytes (or reporting failure), it releases that decoder's
buffer allocation. Borrowed direct streams remain intact. This avoids cumulative
attachment buffers exhausting the worker allowance and restarting whole-archive
inventories. Focused tests cover repeated exact-byte reads, failure cleanup and
retained direct streams; whole-archive verification remains separate.
